# DEPLOY.md — развёртывание и обновление AI_1C

Инструкция для ИИ-агента. Человеку достаточно попросить:

- «Разверни AI_1C по `DEPLOY.md` в каталоге `<путь>`»
- «Обнови AI_1C по `DEPLOY.md`»

**Источник истины:** https://github.com/smirnov0ser/AI_1C, ветка `master`.
Всё, что ниже, агент выполняет сам; у пользователя запрашиваются только параметры его проекта (шаг A0).

---

## 1. Что переносится из репозитория

| Путь | Назначение | При обновлении |
|------|------------|----------------|
| `.claude/skills/` | навыки 1С (~81 каталог, PS1 + Python-порты); имя каталога зависит от среды, см. ниже | перезаписывать целиком |
| `docs/` | справочники и спецификации формата | перезаписывать целиком |
| `tools/` | инструкция по подключению MCP-1C | перезаписывать целиком |
| `Правила разработки и доработки конфигураций.md` | регламент разработки | перезаписывать целиком |
| `AGENTS.md` | правила для агента, **дополняется под проект** | **сливать вручную**, см. B4 |
| `README.MD` | вводная по проекту | не перезаписывать, только смотреть |
| `.gitignore` | игнорирование `build/`, `TASKS/` и мусора | **сливать**, не заменять |
| `src/cf`, `src/cfe` | каталоги под XML-выгрузку (пустые) | не трогать — там исходники 1С |
| `.v8-project.json` | машинный конфиг с паролями | **не копировать**, создаётся заново |

### Имя каталога навыков зависит от среды

`.claude` — имя по умолчанию (Claude Code, Kilo и другие Claude-совместимые среды). В другой среде каталог называется иначе и должен лежать там, где его ищет агент: `.kilo/`, `.cursor/` и аналогичные — по документации конкретной среды.

- Перед развёртыванием уточнить у пользователя, какой каталог использует его среда. По умолчанию — `.claude`.
- Переименовывать каталог целиком, сохраняя внутри структуру `skills/<имя-навыка>/SKILL.md` (скрипты и `references/` лежат рядом с `SKILL.md`, их пути не меняются).
- Ниже в инструкции `.claude` означает фактическое имя каталога; в командах обновления (B1) подставлять его.

## 2. Требования к машине

Проверить и сообщить пользователю, чего не хватает (не устанавливать без его согласия):

| Компонент | Зачем | Проверка |
|-----------|-------|----------|
| Windows + PowerShell 5.1 | основной рантайм скриптов навыков (`.ps1`) | `$PSVersionTable.PSVersion` |
| Git | развёртывание и обновление | `git --version` |
| 1С:Предприятие 8.3 (конфигуратор) | все операции с конфигурацией | `Test-Path "<v8path>\1cv8.exe"` |
| Python 3.8+ | опционально, только для `.py`-портов на Linux/macOS | `python --version` |
| Node.js 18+ | опционально, только для навыка `web-test` | `node --version` |
| Apache 2.4 | опционально, веб-публикация | `Test-Path "<webPath>\bin\httpd.exe"` |
| ffmpeg | опционально, запись видео `web-test` | `ffmpeg -version` |

Пути `webPath`/`ffmpegPath` не обязательны: Apache навык `web-publish` скачает сам при первом вызове.

# Часть A. Развёртывание

## A0. Собрать параметры проекта

Спросить у пользователя (одним списком, не по одному вопросу):

1. Каталог проекта (куда разворачивать).
2. Путь к платформе: каталог `bin` установленной 1С (например `C:\Program Files\1cv8\8.3.27.2214\bin`).
3. База: существующая (файловая — путь к каталогу; серверная — `сервер/имя`) или нужно создать новую.
4. Пользователь и пароль 1С (если есть).
5. Префикс метаданных `MD_PREFIX` (2–4 латинские буквы, например `SD`).
6. Куда добавлять новые метаданные: `NEW_OBJECTS_IN` (меняющие структуру БД) и `NEW_BD_OBJECTS_IN` (формы, обработки, отчёты) — значения `cf` (основная конфигурация) или `cfe` (расширение).
7. Есть ли расширения и их имена (если есть — каталоги `src\cfe\<Имя>`).

Если пользователь не знает платформу — найти самую старшую:

```powershell
Get-ChildItem "C:\Program Files\1cv8\*\bin\1cv8.exe" | Sort-Object FullName -Descending | Select-Object -First 1
```

## A1. Получить файлы

Выбрать вариант по тому, что уже есть на диске.

### A1a. Каталога проекта ещё нет (рекомендуется)

Клонировать репозиторий прямо в каталог проекта:

```powershell
git clone https://github.com/smirnov0ser/AI_1C.git "<каталог-проекта>"
```

Проект становится git-репозиторием с `origin` на GitHub: свои коммиты идут туда же, обновление — `git pull` (см. B2).

### A1b. Каталог проекта уже существует (свой репозиторий)

Развернуть набор внутрь, не затирая существующие файлы:

```powershell
$tmp = Join-Path $env:TEMP "ai_1c_toolkit"
git clone --depth 1 https://github.com/smirnov0ser/AI_1C.git $tmp

Copy-Item "$tmp\.claude" "<каталог-проекта>\" -Recurse
Copy-Item "$tmp\docs"    "<каталог-проекта>\" -Recurse
Copy-Item "$tmp\tools"   "<каталог-проекта>\" -Recurse
Copy-Item "$tmp\Правила разработки и доработки конфигураций.md" "<каталог-проекта>\"

# AGENTS.md и .gitignore — не копировать поверх, а слить с существующими (см. ниже)
Remove-Item $tmp -Recurse -Force
```

Правила слияния:

- `.claude` (или фактическое имя каталога среды — `.kilo`, `.cursor` и т.п.) — если каталог уже есть, `Copy-Item -Recurse` сольёт его и перезапишет одноимённые файлы. Сначала проверить `Get-ChildItem "<каталог-проекта>\.claude"` и согласовать с пользователем перезапись его собственных навыков/команд.
- `AGENTS.md` — если файла нет, скопировать; если есть, перенести в него разделы из клона, сохранив локальные (см. B4).
- `.gitignore` — дописать недостающие строки (`/build/`, `/TASKS/`, `.vscode/`, `Thumbs.db`, `desktop.ini`), а не заменять файл.
- `README.MD` — не трогать.

Подключить upstream для будущих обновлений:

```powershell
git remote add toolkit https://github.com/smirnov0ser/AI_1C.git
```

## A2. Создать `.v8-project.json`

Создать в корне проекта **свой** файл (не копировать чужой — в нём машинные пути). В варианте A1a файл уже есть в клоне — перезаписать его своим содержимым. Минимум:

```json
{
  "v8path": "C:\\Program Files\\1cv8\\8.3.27.2214\\bin",
  "databases": [
    {
      "id": "dev",
      "name": "Разработка",
      "type": "file",
      "path": "C:\\Bases\\MyApp_Dev",
      "user": "Администратор",
      "password": "",
      "configSrc": "src\\cf",
      "extensions": [
        { "name": "МоеРасширение", "src": "src\\cfe\\МоеРасширение" }
      ]
    }
  ],
  "default": "dev",
  "MD_PREFIX": "SD",
  "COMMENT_OPEN": "//++ SD-{TASK}",
  "COMMENT_CLOSE": "//-- SD-{TASK}",
  "NEW_OBJECTS_IN": "cf",
  "NEW_BD_OBJECTS_IN": "cfe"
}
```

Обязательные поля:

- `v8path` — каталог `bin` платформы (или путь к `1cv8.exe`/`ibcmd.exe`);
- `databases[]` — как минимум `id`, `name`, `type` и `path` (файловая) либо `server` + `ref` (серверная);
- `default` — `id` базы по умолчанию;
- `MD_PREFIX`, `COMMENT_OPEN`, `COMMENT_CLOSE` — префикс и шаблоны комментариев задачи;
- `NEW_OBJECTS_IN`, `NEW_BD_OBJECTS_IN` — правила размещения новых метаданных (читает `AGENTS.md`).

Дополнительные поля (`repository`, `webUrl`, `branches`, `aliases`, `webPath`, `ffmpegPath`, `xsdPath`, `v8args`) — по необходимости, полная схема в `docs/v8-project-guide.md`.

**Обязательно:** файл содержит пароли баз, поэтому его исключают из контроля версий:

```powershell
# в варианте A1a файл пришёл из клона вместе с чужими путями — убрать из индекса, оставив на диске
git rm --cached .v8-project.json
Add-Content .gitignore ".v8-project.json", ".v8-xsd/"
```

В варианте A1b файла в проекте не было — достаточно строк в `.gitignore`.

## A3. Подключить базу

- Существующая база — зарегистрировать: навык `db-list`, операция `add` (или вписать запись руками и проверить через `db-list`).
- Новой базы нет — создать навыком `db-create`:
  `db-create <путь-к-файловой-базе>` или `db-create <сервер>/<имя>`, затем `db-list add`.

Критерий: `db-list` выводит таблицу с нужной базой, `default` указывает на неё.

## A4. Выгрузить исходники конфигурации

Навык `db-dump-xml`, база по умолчанию, каталог — из `configSrc` (`src\cf`):

- полная выгрузка: режим `Full`;
- расширения: `-AllExtensions` (или `-Extension "<Имя>"` в `src\cfe\<Имя>`).

Результат: в `src\cf` есть `Configuration.xml` и `ConfigDumpInfo.xml`, в `src\cfe\<Имя>` — `Configuration.xml` расширения.

Выгрузку делать до любых правок — она задаёт версию формата XML. Если планируется обновление базы другими разработчиками, выгружать той же платформой, какая указана в `v8path`.

## A5. Проверить развёртывание

Выполнить из корня проекта и показать результат пользователю:

```powershell
Test-Path ".claude\skills\db-list\SKILL.md"                       # True (.claude → фактический каталог среды)
(Get-ChildItem ".claude\skills" -Directory).Count                  # ~81, растёт с новыми навыками
(Get-Content ".v8-project.json" -Raw | ConvertFrom-Json).databases # есть записи
Test-Path "src\cf\Configuration.xml"                              # True после A4
```

Плюс:

- `db-list` отрабатывает без ошибок и видит платформу;
- в новом сеансе агента в этом каталоге навыки видны (в списке доступных skills есть `db-list`, `meta-edit`, `web-test` и др.);
- `AGENTS.md` и `Правила разработки и доработки конфигураций.md` лежат в корне и подхватываются агентом как инструкции.

## A6. Опционально

- **MCP-1C** (чтение данных из базы агентом): попросить «установи mcp-1c по `tools/mcp-1c-setup.md`» либо выполнить инструкцию вручную.
- **XSD-схемы** (проверка выгрузки без базы): навык `v8-xsd-fetch`, каталог по умолчанию `.v8-xsd` (в `.gitignore`).
- **Веб-клиент** (нужен для `web-test`): навык `web-publish` — Apache скачается сам.
- **ffmpeg** — только для записи видеоинструкций.

## A7. Зафиксировать точку обновления

Сообщить пользователю SHA источника и сохранить его в сообщении коммита, отдельных файлов не создавать:

```powershell
# если проект клонирован из AI_1C (вариант A1a)
git rev-parse --short HEAD

# если набор скопирован внутрь чужого репозитория (вариант A1b)
git ls-remote https://github.com/smirnov0ser/AI_1C.git refs/heads/master
# → "<sha> refs/heads/master"; в коммит писать первые 7 символов
```

Рекомендуемый коммит после развёртывания: `Add AI_1C toolkit @<sha>`.

# Часть B. Обновление

Обновление затрагивает только файлы набора (см. таблицу в разделе 1). Исходники 1С (`src/`), задачи (`TASKS/`), сборки (`build/`) и конфиг `.v8-project.json` не изменяются.

## B0. Определить способ развёртывания

```powershell
git remote -v                      # есть ли origin на smirnov0ser/AI_1C или remote toolkit
git log --oneline -1
```

- проект клонирован из AI_1C (`origin` = `https://github.com/smirnov0ser/AI_1C.git`) → B2;
- набор скопирован внутрь своего репозитория (есть remote `toolkit`) → B1;
- remote нет → выполнить `git remote add toolkit https://github.com/smirnov0ser/AI_1C.git` и идти по B1.

## B1. Обновление привязанного набора (основной путь)

```powershell
git fetch toolkit master
$sha = git rev-parse --short toolkit/master

# 1. Сначала показать, что изменится, и согласовать с пользователем
git diff --stat HEAD toolkit/master -- .claude docs tools "Правила разработки и доработки конфигураций.md"

# 2. Перезаписать только файлы набора
git checkout toolkit/master -- .claude docs tools "Правила разработки и доработки конфигураций.md"

# 3. AGENTS.md и .gitignore — слить вручную (B4), не перезаписывать

git add .claude docs tools "Правила разработки и доработки конфигураций.md"
git commit -m "Update AI_1C toolkit to $sha"
```

> **Переименованный каталог навыков.** Если `.claude` переименован (например в `.kilo`), `git checkout toolkit/master -- .claude ...` создаст `.claude` заново и не обновит рабочий каталог. В этом случае навыки обновлять копированием из клона источника:
>
> ```powershell
> $tmp = Join-Path $env:TEMP "ai_1c_toolkit"
> git clone --depth 1 https://github.com/smirnov0ser/AI_1C.git $tmp
> Copy-Item "$tmp\.claude\skills\*" "<каталог-проекта>\.kilo\skills\" -Recurse -Force
> Remove-Item $tmp -Recurse -Force
> ```
>
> `docs`, `tools` и «Правила разработки и доработки конфигураций.md» не переименовываются — их обновляет обычный `checkout` из блока выше.

Если рабочее дерево грязное — не делать `checkout` поверх незакоммиченных изменений: сначала попросить пользователя закоммитить/спрятать, либо обновлять только не затронутые пути.

Если в `docs/` или `.claude/` есть **локальные** доработки навыков — `checkout` их перезапишет. Перед шагом 2 проверить:

```powershell
git status --short -- .claude docs tools
```

При наличии локальных правок — согласовать: сохранить их отдельным коммитом, затем повторить обновление и разрешить конфликты.

## B2. Обновление проекта-клона

```powershell
git fetch origin            # origin = AI_1C
git status -sb
git merge --ff-only origin/master
```

Если `ff-only` не проходит (в проекте есть свои коммиты) — выполнить обычный `git merge origin/master` и разрешить конфликты. Конфликты в `AGENTS.md`, `.gitignore`, `README.MD` разрешать по правилам B4; конфликты в `.claude/`/`docs/` — брать версию источника, если пользователь не сказал иное.

## B3. Что нельзя перезаписывать

| Путь | Почему |
|------|--------|
| `.v8-project.json` | машинные пути, пароли, префикс проекта |
| `src/`, `TASKS/`, `build/` | исходники 1С, задачи, сборки — не часть набора |
| `README.MD` | в проекте он свой |
| `AGENTS.md` | содержит локальные разделы «Особенности проекта» |
| `.gitignore` | может содержать правила проекта |
| `tools/mcp-1c/` | скачанный бинарник MCP (не из репозитория) |

## B4. Слияние `AGENTS.md`

`AGENTS.md` в источнике — шаблон; в проекте он **обязательно** расходится (README прямо предписывает вносить правила проекта туда). Порядок:

1. `git diff HEAD toolkit/master -- AGENTS.md` — что изменилось в источнике.
2. Если изменений в источнике нет — оставить локальный файл.
3. Если локальных изменений нет — взять версию источника.
4. Если менялись оба — перенести только новые/изменённые разделы источника, сохранив локальные, особенно «Особенности проекта», «Основные параметры проекта», «Дополнительные переопределяемые правила».
5. Показать пользователю итоговый diff и получить подтверждение, если смысл правил изменился.

Никогда не выполнять `git checkout toolkit/master -- AGENTS.md` без просмотра diff.

## B5. Проверка после обновления и откат

Повторить проверки A5 (навыки на месте, JSON конфига валиден, база и платформа видны). Дополнительно:

- в `AGENTS.md` не осталось ссылок на удалённые/переименованные навыки;
- если в источнике появились новые поля `.v8-project.json` — спросить пользователя и дописать их (например новые флаги проверок).

Откат — обычными средствами git:

```powershell
git log --oneline -5
git reset --hard <sha-до-обновления>     # только с подтверждения пользователя
```

## Правила для агента

- Не переписывать локальные файлы проекта из таблицы B3.
- Не копировать `.v8-project.json` из репозитория: в нём чужие пути и пароли.
- Перед массовой перезаписью (`git checkout toolkit/master -- ...`) показывать `--stat` и получать подтверждение.
- Все команды с путями выполнять в кавычках (кириллица, пробелы, `C:\Program Files\...`).
- Не устанавливать ПО (Python, Node, Apache, ffmpeg, 1С) без явного согласия — только сообщить, чего не хватает.
- Не запускать 1С дольше 20 секунд ожидания; завершать сеансы через клиент, а не убивать процессы.
- Скрипты навыков — `.ps1` (мастер-версия). `.py` использовать только там, где PowerShell недоступен; не править `.py` без парного изменения `.ps1` (см. `docs/python-porting-guide.md`).
